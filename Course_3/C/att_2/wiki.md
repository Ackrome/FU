# MusicPlayer wiki

Подробная документация к `main.c` консольного музыкального плеера для Windows.

## Назначение проекта

`MusicPlayer` - это консольный MP3-плеер на языке C. Программа хранит плейлист в двусвязном списке, умеет воспроизводить текущий трек через Windows Multimedia API, управлять громкостью, показывать длительность трека, добавлять и удалять треки, импортировать папку, сохранять и загружать плейлист, выполнять поиск, сортировку и перемешивание.

Проект ориентирован на Windows, потому что использует:

- `windows.h`;
- `mmsystem.h`;
- MCI-команды через `mciSendStringA` и `mciSendStringW`;
- `GetFileAttributesW` для проверки существования файлов;
- `CreateThread`, `CRITICAL_SECTION`, `Sleep`, `GetTickCount` для фонового автоперехода;
- кодировки Windows и UTF-8.

## Основные возможности

Программа поддерживает:

- воспроизведение MP3-файлов;
- паузу и продолжение;
- остановку;
- переход к следующему и предыдущему треку с закольцовкой;
- вывод плейлиста;
- ручное добавление MP3-трека;
- импорт всех `.mp3` из папки;
- удаление трека по номеру;
- сортировку плейлиста по названию;
- поиск по названию и исполнителю без учета регистра;
- Shuffle, то есть перемешивание плейлиста;
- управление громкостью командами `+` и `-`;
- вывод длительности трека в формате `мм:сс`;
- автоматический переход на следующий трек после окончания текущего;
- автоматическую загрузку `playlist.txt` и `settings.txt` при запуске;
- автоматическое сохранение плейлиста и громкости при выходе;
- чтение ID3v1-тегов из MP3-файлов.

## Ограничения

Текущая реализация намеренно простая и имеет ограничения:

- воспроизведение реализовано только для `.mp3`;
- импорт папки добавляет только `.mp3`;
- ID3 читается только в формате ID3v1 из последних 128 байт файла;
- ID3v2 не читается;
- теги ID3v1 интерпретируются как Windows-1251 и переводятся в UTF-8;
- поиск использует фиксированные буферы wide-строк;
- плейлист сохраняется в простом текстовом формате без экранирования символа `|`;
- если в названии, исполнителе или пути есть символ `|`, загрузка такой строки может работать некорректно;
- фоновой автопереход опрашивает MCI раз в секунду, поэтому переключение может происходить не мгновенно;
- программа рассчитана на Windows-консоль с поддержкой UTF-8.

## Сборка

### Через CMake

Основной `CMakeLists.txt` создает исполняемый файл `MusicPlayer` из `main.c` и подключает библиотеку `winmm`.

```cmake
add_executable(MusicPlayer main.c)
target_link_libraries(MusicPlayer winmm)
```

Для MSVC дополнительно включен режим `/utf-8`, чтобы русские строковые литералы корректно компилировались:

```cmake
if(MSVC)
    target_compile_options(MusicPlayer PRIVATE /utf-8)
endif()
```

### Через Visual Studio Code task

`.vscode/tasks.json` собирает активный файл через `cl.exe`. В аргументах важны:

- `/utf-8` - компиляция исходника как UTF-8;
- `/link winmm.lib` - подключение Windows Multimedia API.

Без `winmm.lib` функции MCI не слинкуются.

## Тесты

Для проекта добавлен отдельный тестовый исполняемый файл `MusicPlayerTests`.

Исходник тестов:

```text
tests/test_musicplayer.c
```

Тесты подключают `main.c` напрямую в режиме:

```c
#define MUSICPLAYER_TEST
#include "../main.c"
```

В этом режиме интерактивная функция `main` из `main.c` не компилируется. Это позволяет тестировать внутренние функции, структуры и статические helper-функции без запуска консольного меню.

### Что покрыто тестами

Тесты проверяют:

- удаление кавычек из путей;
- безопасное копирование строк;
- форматирование длительности `мм:сс`;
- ограничение громкости диапазоном `0..1000`;
- увеличение и уменьшение громкости;
- добавление треков в двусвязный список;
- удаление трека по номеру;
- очистку плейлиста;
- сортировку по названию;
- сохранение текущего узла при сортировке;
- Shuffle и сохранение всех узлов списка;
- поиск без учета регистра;
- Unicode-поиск по русскому тексту;
- проверку существования файла;
- сохранение и загрузку плейлиста;
- пропуск недоступных файлов при загрузке плейлиста;
- сохранение и загрузку `settings.txt`.

### Запуск через CMake

После конфигурации проекта можно собрать и запустить тесты:

```powershell
cmake --build build --target MusicPlayerTests
ctest --test-dir build --output-on-failure
```

Если `cmake` недоступен в `PATH`, тесты можно собрать напрямую через MSVC Developer Command Prompt:

```bat
cl.exe /nologo /W4 /utf-8 /TC /Fe:build\test_musicplayer.exe tests\test_musicplayer.c /link winmm.lib
build\test_musicplayer.exe
```

### Временные файлы тестов

Тесты создают временные файлы внутри папки `tests`, например:

- `tests\exists_test.mp3`;
- `tests\load_ok_1.mp3`;
- `tests\load_ok_2.mp3`;
- `tests\playlist_test.txt`;
- `tests\settings_backup.tmp`.

После успешного выполнения тесты удаляют временные файлы.

Если в корне проекта уже есть пользовательский `settings.txt`, тестовый запуск временно переименовывает его в `tests\settings_backup.tmp`, а затем восстанавливает обратно. Это нужно, потому что функции громкости и настроек работают с фиксированным файлом `settings.txt`.

## Файлы данных

### `playlist.txt`

Файл плейлиста создается автоматически при выходе из программы и может быть создан вручную командой `10 -> 1`.

Формат каждой строки:

```text
Исполнитель|Название|Полный_путь_к_mp3
```

Пример:

```text
Кино|Группа крови|C:\Music\Kino\Gruppa krovi.mp3
Unknown|track01|C:\Music\track01.mp3
```

При загрузке программа:

- читает строки через `fgets`;
- разбивает их через `strtok(line, "|")`;
- ожидает три поля: исполнитель, название, путь;
- проверяет, существует ли файл по указанному пути;
- добавляет только доступные файлы;
- недоступные файлы пропускает и показывает их количество в статусе.

### `settings.txt`

Файл настроек сохраняет текущую громкость.

Формат:

```text
volume=1000
```

Значение громкости хранится в диапазоне `0..1000`, где:

- `0` - 0%;
- `100` - 10%;
- `500` - 50%;
- `1000` - 100%.

При запуске программа читает этот файл и восстанавливает громкость.

## Главное меню

Главный экран перерисовывается через `system("cls")` перед каждым вводом команды. Это сделано, чтобы меню оставалось на одном месте, а статус и результаты операций не разъезжались по консоли.

Структура экрана:

1. Блок статуса.
2. Панель результатов, если она не пустая.
3. Главное меню.

Пример меню:

```text
[ СТАТУС ]
Готово.

[ УПРАВЛЕНИЕ ПЛЕЕРОМ ]
1. Играть         | 6. Показать плейлист
2. Пауза          | 7. Добавить трек / Импорт папки
3. Стоп           | 8. Удалить трек
4. Следующий      | 9. Отсортировать по алфавиту
5. Предыдущий     | 10. Сохр. / Загр. в файл
11. Поиск         | 12. Shuffle
+. Громкость выше | -. Громкость ниже (сейчас 100%)
0. Выход
Ваш выбор:
```

В коде ввод команды читается как строка:

```c
scanf("%15s", choice);
```

Это нужно, потому что меню принимает не только числа, но и символы `+` и `-`.

## Команды меню

| Команда | Назначение |
|---|---|
| `1` | Воспроизвести текущий трек |
| `2` | Пауза или продолжение |
| `3` | Остановить музыку |
| `4` | Перейти к следующему треку |
| `5` | Перейти к предыдущему треку |
| `6` | Показать плейлист |
| `7` | Добавить один трек или импортировать папку |
| `8` | Удалить трек по номеру |
| `9` | Отсортировать плейлист по названию |
| `10` | Сохранить или загрузить `playlist.txt` |
| `11` | Поиск по названию или исполнителю |
| `12` | Shuffle, перемешивание плейлиста |
| `+` | Увеличить громкость на 10% |
| `-` | Уменьшить громкость на 10% |
| `0` | Выход с автосохранением |

## Сценарии использования

### Первый запуск

1. Запустите программу.
2. Если `playlist.txt` отсутствует, появится статус, что автосохраненный плейлист не найден.
3. Используйте команду `7`.
4. Выберите `1`, чтобы добавить один трек, или `2`, чтобы импортировать папку.
5. Используйте команду `1`, чтобы начать воспроизведение.

### Добавление одного трека

Команда:

```text
7
1
```

Программа попросит:

1. Исполнителя.
2. Название трека.
3. Полный путь к `.mp3`.

Путь можно вводить в кавычках. Кавычки в начале и конце будут удалены.

Пример:

```text
Введите исполнителя: Кино
Введите название трека: Группа крови
Введите полный путь к файлу (.mp3): "C:\Music\Kino\Gruppa krovi.mp3"
```

Перед добавлением программа проверяет:

- исполнитель не пустой;
- название не пустое;
- путь не пустой;
- расширение `.mp3`;
- файл существует;
- путь не является папкой.

Если проверка не пройдена, трек не добавляется.

### Импорт папки

Команда:

```text
7
2
```

Программа попросит полный путь к папке и найдет в ней файлы с расширением `.mp3`.

Для каждого MP3:

- строится полный путь;
- если есть ID3v1-теги, используются исполнитель и название из тегов;
- если тегов нет, названием становится имя файла без расширения;
- исполнитель становится `Unknown`.

Импорт не проходит рекурсивно по подпапкам. Загружаются только файлы из выбранной папки.

### Запуск воспроизведения

Команда:

```text
1
```

При запуске:

1. Проверяется, что в плейлисте есть текущий трек.
2. Проверяется расширение `.mp3`.
3. Проверяется существование файла.
4. Предыдущий MCI-поток останавливается и закрывается.
5. Файл открывается командой MCI `open`.
6. Применяется текущая громкость.
7. Получается длительность трека.
8. Отправляется команда MCI `play`.
9. В статус выводится текущий трек.

Пример статуса:

```text
[▶] Играет: Кино - Группа крови (04:45)
```

Если длительность получить не удалось:

```text
[▶] Играет: Кино - Группа крови (--:--)
```

### Пауза и продолжение

Команда:

```text
2
```

Если трек играет, команда ставит его на паузу:

```text
[PAUSE] Пауза
```

Если трек уже на паузе, команда продолжает воспроизведение:

```text
[PLAY] Воспроизведение продолжено
```

Если открытого трека нет, выводится ошибка.

### Остановка

Команда:

```text
3
```

Останавливает и закрывает MCI-устройство `track`.

После остановки:

- `g_track_open = 0`;
- `g_is_paused = 0`;
- `g_last_track_start_tick = 0`.

### Следующий и предыдущий трек

Команда `4` включает следующий трек.

Если текущий трек последний, программа переходит к `head`, то есть к началу списка.

Команда `5` включает предыдущий трек.

Если текущий трек первый, программа переходит к `tail`, то есть к концу списка.

Так реализована закольцовка плейлиста.

### Показ плейлиста

Команда:

```text
6
```

Плейлист выводится в панель результатов. Текущий трек выделяется:

```text
=== ВАШ ПЛЕЙЛИСТ (3 треков) ===
 >>> 1. Кино - Группа крови <<<
     2. Unknown - track01
     3. Сплин - Выхода нет
=================================
```

### Удаление трека

Команда:

```text
8
```

Программа сначала показывает плейлист, затем просит номер трека.

Если удаляется текущий трек:

- воспроизведение останавливается;
- текущим становится следующий трек;
- если следующего нет, текущим становится первый трек;
- если удалялся единственный трек, текущий указатель становится `NULL`.

### Сохранение и загрузка вручную

Команда:

```text
10
```

Далее:

- `1` - сохранить плейлист в `playlist.txt`;
- `2` - загрузить плейлист из `playlist.txt`.

Загрузка очищает текущий плейлист и загружает доступные файлы из файла.

### Поиск

Команда:

```text
11
```

Программа спрашивает слово и ищет его:

- в названии трека;
- в имени исполнителя.

Поиск выполняется без учета регистра. Например, запрос `ночь` найдет:

- `Ночь`;
- `НОЧЬ`;
- `ночь`;
- `Кино - Ночь`.

Технически поиск реализован через:

- перевод UTF-8 строк в wide-строки;
- `CompareStringOrdinal(..., TRUE)` для сравнения без учета регистра;
- посимвольный проход по строке как по окну длиной запроса.

Если преобразование UTF-8 в wide-строку не удалось, используется простой `strstr` как fallback.

### Shuffle

Команда:

```text
12
```

Перемешивает порядок треков в плейлисте.

Алгоритм:

1. Все указатели на узлы списка копируются во временный массив.
2. Массив перемешивается алгоритмом Fisher-Yates.
3. Узлы связываются заново через `prev` и `next`.
4. Обновляются `head` и `tail`.

Важно: текущий трек остается тем же узлом памяти. Меняется только порядок узлов вокруг него.

### Громкость

Команды:

```text
+
-
```

Громкость хранится как число `0..1000`.

Пользователь видит проценты:

- `0` -> 0%;
- `100` -> 10%;
- `500` -> 50%;
- `1000` -> 100%.

Шаг изменения - `100`, то есть 10%.

Если трек открыт, громкость сразу применяется командой MCI:

```text
setaudio track volume to <value>
```

Если трек не открыт, новое значение просто сохраняется в памяти и будет применено при следующем запуске трека.

После изменения громкости вызывается `save_settings()`, поэтому `settings.txt` обновляется сразу.

### Выход

Команда:

```text
0
```

При выходе программа:

1. Останавливает фоновый поток автоперехода.
2. Сохраняет плейлист в `playlist.txt`.
3. Сохраняет громкость в `settings.txt`.
4. Останавливает музыку.
5. Очищает память плейлиста.
6. Удаляет `CRITICAL_SECTION`.
7. Очищает экран.
8. Выводит `Выход...`.

## Архитектура данных

### `Track`

```c
typedef struct Track {
    char title[TITLE_SIZE];
    char artist[ARTIST_SIZE];
    char filepath[PATH_SIZE];
    
    struct Track* next;
    struct Track* prev;
} Track;
```

`Track` - один элемент плейлиста.

Поля:

- `title` - название трека;
- `artist` - исполнитель;
- `filepath` - полный путь к MP3-файлу;
- `next` - следующий трек;
- `prev` - предыдущий трек.

Размеры строк задаются константами:

- `TITLE_SIZE = 100`;
- `ARTIST_SIZE = 100`;
- `PATH_SIZE = 512`.

### `Playlist`

```c
typedef struct Playlist {
    Track* head;
    Track* tail;
    Track* current;
    int size;
} Playlist;
```

`Playlist` хранит состояние двусвязного списка.

Поля:

- `head` - первый трек;
- `tail` - последний трек;
- `current` - текущий выбранный трек;
- `size` - количество треков.

## Воспроизведение через MCI

Программа использует MCI alias `track`.

### Открытие файла

Для MP3 формируется команда:

```text
open "<filepath>" type mpegvideo alias track
```

Команда создается в UTF-8, затем переводится в wide-строку и выполняется через:

```c
mciSendStringW(wcommand, NULL, 0, NULL);
```

Wide-вызов нужен, чтобы работали пути с русскими символами.

### Запуск

```text
play track
```

### Пауза

```text
pause track
```

### Продолжение

```text
resume track
```

### Остановка и закрытие

```text
stop track
close track
```

### Громкость

```text
setaudio track volume to 700
```

### Длина трека

Перед получением длины выставляется формат времени:

```text
set track time format milliseconds
```

Потом запрашивается длина:

```text
status track length
```

Ответ приходит строкой с количеством миллисекунд.

### Проверка окончания трека

Фоновый поток выполняет:

```text
status track mode
```

Если MCI возвращает `stopped`, программа включает следующий трек.

## Автопереход на следующий трек

Автопереход реализован функцией `auto_next_monitor`.

Алгоритм:

1. Поток запускается в `main` через `start_auto_next_monitor`.
2. Каждую секунду поток просыпается.
3. Входит в критическую секцию.
4. Проверяет:
   - трек открыт;
   - трек не на паузе;
   - запуск трека был более `AUTO_NEXT_START_GRACE_MS` назад.
5. Запрашивает MCI-состояние `status track mode`.
6. Если состояние равно `stopped`, вызывает `play_next`.
7. Выходит из критической секции.

Задержка `AUTO_NEXT_START_GRACE_MS` нужна, чтобы MCI не успел вернуть `stopped` сразу после запуска до фактического старта воспроизведения.

## Синхронизация потоков

Так как главный поток работает с меню и плейлистом, а фоновый поток может автоматически переключить трек, используется `CRITICAL_SECTION`.

Обертки:

```c
lock_player();
unlock_player();
```

Критическая секция защищает:

- воспроизведение;
- переключение треков;
- удаление и очистку плейлиста;
- сохранение и загрузку;
- вывод экрана;
- работу фонового автоперехода.

## Чтение ID3v1

Функция `get_id3v1_tags` читает последние 128 байт MP3-файла.

Структура ID3v1:

| Смещение | Длина | Значение |
|---:|---:|---|
| `0` | `3` | Метка `TAG` |
| `3` | `30` | Название |
| `33` | `30` | Исполнитель |
| `63` | `30` | Альбом |
| `93` | `4` | Год |
| `97` | `30` | Комментарий |
| `127` | `1` | Жанр |

В программе используются только:

- название;
- исполнитель.

После чтения:

1. Проверяется метка `TAG`.
2. Копируются 30 байт названия и 30 байт исполнителя.
3. Удаляются пробелы справа.
4. Строки переводятся из Windows-1251 в Unicode.
5. Потом переводятся из Unicode в UTF-8.
6. Если название или исполнитель пустые, функция возвращает `0`.

## Память

Каждый трек создается через `malloc` в `create_track`.

Освобождение памяти происходит:

- при удалении одного трека через `remove_track_by_index`;
- при полной очистке через `clear_playlist`;
- при выходе из программы.

Временный массив для Shuffle также выделяется через `malloc` и освобождается через `free`.

## Ошибки и статусы

Большинство операций не печатает сообщение напрямую в произвольном месте консоли. Вместо этого используется:

```c
set_status(...)
```

Следующий вызов `render_screen` очистит экран и покажет статус сверху.

Для MCI-ошибок используется:

```c
print_mci_error(...)
```

Она пытается получить текст ошибки через `mciGetErrorStringW`. Если текст получить не удалось, выводится числовой код ошибки.

## Типовые проблемы

### Трек не играет

Проверьте:

- файл существует;
- файл имеет расширение `.mp3`;
- путь не содержит ошибок;
- Windows может воспроизвести этот MP3 через MCI;
- проект слинкован с `winmm.lib`.

### Русские символы отображаются некорректно

Проверьте:

- файл `main.c` сохранен как UTF-8;
- используется ключ компиляции `/utf-8`;
- консоль работает в UTF-8;
- в `main` вызываются `SetConsoleOutputCP(CP_UTF8)` и `SetConsoleCP(CP_UTF8)`.

### Плейлист загрузился не полностью

Причины:

- часть файлов была удалена или перемещена;
- путь в `playlist.txt` неверный;
- строка содержит лишний символ `|`;
- файл не является доступным обычным файлом.

### Поиск не нашел трек

Проверьте:

- слово введено без лишних пробелов;
- нужный трек действительно есть в плейлисте;
- текст не был обрезан при сохранении в буфер;
- название и исполнитель не пустые.

### Автопереход не сработал

Возможные причины:

- MCI не вернул состояние `stopped`;
- трек на паузе;
- трек не был открыт через `play_current`;
- воспроизведение остановлено вручную.
