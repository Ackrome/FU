# Описание программы

## Аннотация

Консольный MP3-плеер разработан на языке C для операционной системы Windows. Описание дополнено подробным разбором каждой функции исходного кода.

Рассмотрены рабочие функции файла `main.c` и функции автоматизированного тестового модуля `tests/test_musicplayer.c`. Для каждой функции приведены сигнатура, назначение, параметры, возвращаемое значение, алгоритм, побочные эффекты, особые условия и основные связанные вызовы.

## 1. Общие сведения

### 1.1. Наименование программы

**Полное наименование:** «Разработка консольного MP3-плеера с управлением плейлистом и воспроизведением через Windows API на языке C».

**Краткое наименование:** `MusicPlayer`.

### 1.2. Назначение описания

Описание предназначено для изучения структуры программы, сопровождения исходного кода и проверки соответствия реализации заявленным функциям.

### 1.3. Программное обеспечение

Для сборки и выполнения программы требуются:

- операционная система Windows;
- компилятор C с поддержкой WinAPI, например Microsoft Visual C;
- CMake версии 3.10 или новее;
- системная библиотека `winmm`;
- консоль с поддержкой UTF-8.

### 1.4. Язык программирования

Основная программа и тестовый модуль написаны на языке C. Для мультимедийных операций, работы с файлами Unicode и потоками используются функции Windows API.

## 2. Функциональное назначение

Программа предназначена для локального воспроизведения MP3-файлов и управления плейлистом из консоли. Реализованы:

- добавление одного трека и импорт MP3-файлов из папки;
- хранение треков в двусвязном списке;
- воспроизведение, остановка, пауза, продолжение и циклическая навигация;
- отображение длительности трека;
- управление громкостью через команды `+` и `-`;
- сортировка, поиск и перемешивание плейлиста;
- сохранение плейлиста и громкости между запусками;
- чтение ID3v1-тегов;
- автоматический переход к следующему треку в фоновом потоке;
- автоматизированные тесты ключевой логики.

Функциональные ограничения:

- воспроизводятся только файлы `.mp3`;
- импорт папки не является рекурсивным;
- поддерживаются теги ID3v1, но не ID3v2;
- воспроизведение зависит от возможностей MCI в установленной Windows-системе.

## 3. Описание логической структуры

### 3.1. Общий алгоритм

При запуске программа настраивает UTF-8 консоль, инициализирует критическую секцию и пустой плейлист, загружает настройки и ранее сохраненный плейлист. Затем создается фоновый поток автоперехода. Основной поток циклически отображает меню, читает команду пользователя и вызывает соответствующую функцию. При выходе поток автоперехода завершается, плейлист и громкость сохраняются, MCI-устройство закрывается, память списка освобождается.

### 3.2. Структуры данных

Узел `Track` хранит название, исполнителя, путь к файлу и ссылки `next` и `prev`. Структура `Playlist` хранит указатели `head`, `tail`, `current` и размер списка `size`.

### 3.3. Глобальное состояние

| Идентификатор | Назначение |
|---|---|
| `g_track_open` | Признак открытого MCI-устройства `track` |
| `g_is_paused` | Признак паузы |
| `g_volume` | Громкость по шкале MCI от 0 до 1000 |
| `g_status_message` | Текущее сообщение интерфейса |
| `g_panel_text` | Панель результатов операций |
| `g_player_lock` | Критическая секция для общего состояния |
| `g_auto_next_thread` | Дескриптор фонового потока |
| `g_auto_next_running` | Атомарный флаг работы потока |
| `g_last_track_start_tick` | Время запуска трека для защитной задержки |

**Назначение.** Безопасно копирует строку в буфер ограниченного размера.

## 8. Входные данные

Программа принимает:

- команды меню из стандартного ввода;
- пути к отдельным MP3-файлам и папкам в кодировке UTF-8;
- сохраненные данные плейлиста со строками формата `исполнитель|название|путь`;
- сохраненное значение громкости в формате `volume=<число>`;
- бинарные данные MP3-файлов для чтения последних 128 байт ID3v1.

## 9. Выходные данные

Программа формирует:

- текстовые сообщения консольного интерфейса в UTF-8;
- звук через Windows Multimedia API;
- сохраненные данные плейлиста;
- сохраненное значение громкости;
- диагностический вывод тестового модуля с количеством выполненных и неуспешных проверок.
